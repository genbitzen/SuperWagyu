# V0.1 Technical Investigation Report: Real Lazada Availability

## 1. Executive Summary

This investigation evaluated the feasibility of connecting the `ILazadaProvider` abstraction to real Lazada Singapore product URLs (`lazada.sg`) to detect product purchasability (`IN_STOCK`, `OUT_OF_STOCK`, `UNKNOWN`), seller identity, and pricing without defeating bot protection or violating security boundaries.

### Outcome Classification: **Outcome A (with Operational Boundaries)**
* **Purchasability Reading**: Real Lazada product pages expose structured product schema (JSON-LD) and PDP state data that can be parsed to extract title, seller name, SGD price, and stock status (`IN_STOCK` vs `OUT_OF_STOCK`).
* **Security & Rate Constraints**: Unauthenticated high-frequency HTTP requests trigger Lazada's Anti-Bot WAF (`x5step` / `sec.lazada.sg` CAPTCHA challenge). When challenged, the provider cleanly reports `CAPTCHA_BLOCKED` and normalizes status to `UNKNOWN` without breaking system state.

## 3. Real Provider Architecture & Detection Logic

The `RealLazadaProvider` ([realLazadaProvider.ts](file:///c:/Users/Genesis/.gemini/antigravity/scratch/SuperWagyu/apps/backend/src/providers/realLazadaProvider.ts)) implements the following safe parsing strategy:

1. **Anti-Bot / CAPTCHA Guard**:
   Scans HTML for WAF challenge markers (`x5step`, `punish`, `sec.lazada.sg`). If detected, immediately returns `rawStatus: 'CAPTCHA_BLOCKED'`.
2. **Structured JSON-LD Parsing**:
   Extracts `<script type="application/ld+json">` objects to obtain schema properties:
   - `https://schema.org/InStock` → `IN_STOCK`
   - `https://schema.org/OutOfStock` / `SoldOut` → `OUT_OF_STOCK`
3. **HTML Action Button Heuristics**:
   Fallback check for `"buyNowable":true`, `"inStock":true`, or presence of active `Add to Cart` / `Buy Now` DOM elements.
4. **Structured Logging**:
   Emits structured log entries for request initiation, HTTP status, parsing result, and duration without logging sensitive headers.

## 4. Operational & Security Boundaries

1. **No Bot Bypasses**: The provider uses standard HTTP GET calls with standard mobile User-Agent headers. It does not attempt to bypass CAPTCHA challenges or defeat WAF anti-bot measures.
2. **Polling Frequency Recommendation**: Unauthenticated requests should use conservative polling intervals (e.g. 10–30s per listing) or warm authenticated session tokens to avoid hitting WAF challenges.
3. **Provider Decoupling**: `MockLazadaProvider` remains active and default for local unit testing (`USE_MOCK_PROVIDER=true`).
